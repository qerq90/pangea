# Pangea

Текстовая RPG для ВКонтакте на Scala + ZIO.

## Требования

- Docker и Docker Compose

## Деплой на VDS

### 1. Установить Docker

```bash
curl -fsSL https://get.docker.com | sh
```

### 2. Склонировать репозиторий

```bash
git clone <repo_url> /opt/pangea
cd /opt/pangea
```

### 3. Создать файл с секретами

```bash
cp .env.example .env
nano .env
```

Заполнить:

```env
POSTGRES_DB=pangea
POSTGRES_USER=pangea
POSTGRES_PASSWORD=your_strong_password

VK_TOKEN=your_vk_token_here

# Пароль админ-панели («/admin» в личке бота) и выдачи логов по HTTP.
# Пусто — и панель, и `GET /logs` закрыты для всех.
ADMIN_PASSWORD=
```

### 4. Запустить

```bash
docker compose up -d --build
```

При первом запуске Docker соберёт образ (~5 минут), поднимет PostgreSQL и прогонит все миграции автоматически.

### 5. Проверить

```bash
docker compose ps        # все сервисы должны быть Up
docker compose logs -f app  # логи бота
```

## Обновление

```bash
git pull
docker compose up -d --build
```

Миграции применяются автоматически при каждом запуске контейнера.

## Остановка

```bash
docker compose down        # остановить, данные сохранятся
docker compose down -v     # остановить и удалить БД
```

## Локальная разработка

Для запуска тестов PostgreSQL не нужен — тесты используют in-memory заглушки.

```bash
sbt core/test
```

Для локального запуска бота нужно поднять PostgreSQL (например, через `docker compose up postgres -d`) и задать переменные окружения:

```bash
export POSTGRES_JDBC_URL=jdbc:postgresql://localhost:5432/pangea
export POSTGRES_USER=pangea
export POSTGRES_PASSWORD=pangea
export VK_TOKEN=your_token
sbt app/run
```

## Архитектура

```
app/          — точка входа, HTTP-сервер (VK Callback API)
core/         — игровая логика, модели, состояния, DAO
migrations/   — SQL-миграции (goose)
```

Бот работает как конечный автомат: каждый игрок находится в одном из состояний (`Registration`, `Dungeon`, `HeroStats`, ...), которое хранится в БД. При получении события от VK вызывается обработчик текущего состояния.

## Донат (покупка дублонов)

Продажа дублонов за рубли через Робокассу. Вход — Торговый дом на Торговой
площади, банкир Рахадим → «Купить дублоны». Мы на НПД: чек в «Мой налог»
выбивают Робочеки СМЗ на стороне Робокассы, от нас нужен только e-mail игрока.

Пока `ROBOKASSA_MERCHANT_LOGIN` и оба пароля пусты, донат выключен: экран у
Рахадима остаётся заглушкой, заказы не создаются. Так же он выключится сам, если
прайс-лист не пройдёт проверку при запуске — в логах будет строка с причиной.

Что нужно, чтобы включить:

1. Заполнить в `.env` переменные `ROBOKASSA_*` (см. `.env.example`).
2. Поправить прайс-лист в блоке `robokassa.packs` файла
   `app/src/main/resources/application.conf`. Цены там в **рублях** (`99`, `99.50`).
3. Поднять HTTPS перед приложением. Сейчас приложение слушает голый HTTP, так
   что нужен обратный прокси с сертификатом.
4. В кабинете Робокассы, «Технические настройки» магазина:
   - алгоритм расчёта хеша — тот же, что `ROBOKASSA_HASH`;
   - ResultURL — `https://<домен>/pay/robokassa/result`, метод POST;
   - SuccessURL и FailURL — `https://vk.ru/stigmapangeaproject`;
   - пароли #1 и #2 (и тестовые, для `ROBOKASSA_TEST=true`).
5. Подключить Робочеки СМЗ: разрешение на интеграцию в «Мой налог».

### Как идёт выдача

Ссылку на оплату собираем сами (`InvId` = `payments.id`), запроса к кассе при
этом нет. Дублоны выдаются ровно один раз — через `PaymentDao.grantOnce` — по
любому из трёх путей:

- уведомление ResultURL с верной подписью (пароль #2) и совпавшей суммой; касса
  шлёт его только по успешной оплате, отвечаем `OK{InvId}`;
- кнопка «Проверить оплату» — спрашивает `OpStateExt`, выдаёт по состоянию 100;
- фоновая сверка раз в минуту — то же, плюс закрывает заказы, по которым ссылка
  истекла, а касса так ничего и не увидела.

Страницы SuccessURL/FailURL ничего не начисляют — игрок может открыть их руками.
В тестовом режиме `OpStateExt` тестовых платежей не видит: выдача там идёт
только по уведомлению.

### Сертификат Минцифры

В образ при сборке добавляется корневой CA Минцифры («Russian Trusted Root CA»,
`docker/russian_trusted_root_ca.cer`, с проверкой отпечатка). Робокассе он не
нужен, но им подписаны сертификаты части российских сервисов. Если запускаешь
бота не через Docker и он понадобился — добавь его в `cacerts` сам:

```bash
keytool -importcert -trustcacerts -cacerts -storepass changeit \
  -alias russian-trusted-root-ca -file docker/russian_trusted_root_ca.cer
```

## Конкурс активности в группе

Лайки и комментарии под свежими постами группы копятся очками: лайк — 1,
комментарий — 2, по одному каждого на пост от игрока. Очки идут только за посты,
вышедшие не раньше недели назад, и только игрокам с героем. Неделя — с
понедельника 00:00 по Москве; в начале новой недели пятеро лучших прошлой
получают по 🟡 100 (с ближайшим действием, где бы ни были), в общую беседу уходят
итоги. Текущую таблицу показывает команда «Рейтинг» в беседе.

Что нужно, чтобы конкурс заработал (Управление → Работа с API → Callback API):

1. **Типы событий:** включить «Запись на стене: добавление», «Комментарий на
   стене: добавление» и «Отметка «Мне нравится»: добавление».
2. **Секретный ключ:** придумать и вписать тот же в `.env` как `VK_SECRET`.
   Без ключа события конкурса не принимаются: их легко подделать.
3. Версия API для Callback — не ниже 5.103 (в ней появились события лайков).

Посты, вышедшие до включения, бот не знает: за них очков нет.

## Код друга

В «Персонаже» → «🎟 Код друга» игрок видит свой код (восемь цифр) и, пока его
герой не выше 5 уровня и код он ещё не вписывал, может вписать чужой. Вписал —
Азат благословляет его на 3 дня, владельцу кода приходит 🟡 3, а когда друг
дорастёт до 10 уровня — ещё 🟡 5. Свой код вписать нельзя, обменяться кодами
друг с другом — тоже.

## Логи по HTTP

Приложение отдаёт свой лог-файл наружу: `GET /logs?tail=500` целиком и
`GET /logs/stream` живым потоком (SSE), оба с необязательным `&grep=...`.

Доступ закрыт паролем `ADMIN_PASSWORD` — тем же, что у админ-панели. Пароль
передаётся заголовком или query-параметром:

```bash
curl -H "Authorization: Bearer $ADMIN_PASSWORD" https://<домен>/logs?tail=500
curl "https://<домен>/logs?tail=500&key=$ADMIN_PASSWORD"
```

Без пароля (и если `ADMIN_PASSWORD` не задан) оба роута отвечают 404. В логах
лежат peer_id игроков, тексты их сообщений и номера заказов доната со суммами —
поэтому открытыми их держать нельзя.
